The `data_relation` pattern accepts `arguments` (one UpperCamelCase entity kind per tuple slot, in tuple order, length equal to `arity`) and emits them, so compositions can declare the typed relations axiom-rules-engine now requires (#33). Compose refuses an untyped composition-level `data_relation` that a composed rule aggregates (a formula names it, or a `derived_relation` filters it). Imported `data_relation`s that share a name are checked as a set, whatever their import order: compose refuses when any two differ in arity or declare different non-empty `arguments`, and otherwise issues one `ComposeWarning` per untyped declaration that has a typed namesake. A later compose release should refuse that typed-beside-untyped case once rulespec-us types `us:statutes/7/2012/j#member_of_household`, as #36 tracks.
